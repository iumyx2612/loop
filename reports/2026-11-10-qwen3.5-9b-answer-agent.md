## 3. Các vấn đề gặp phải và cách sửa

### 3.1 Code chỉ chạy với Anthropic
- `ChatAnthropic` cứng trong runner; system prompt gửi `cache_control` (field riêng Anthropic).
- **Sửa:** thêm `--base-url/--api-key/--timeout/--max-tokens`; có `--base-url` → `ChatOpenAI`, system prompt dạng string (vLLM tự prefix-cache). Thêm 2 cờ trong `QueryContext`: `cache_control`, `finalize_no_think`.

### 3.2 Tool call sai format (`period` / `filters` phẳng)
- Smoke test đầu: 2/2 câu abstain vì recursion limit. Model ghi `"period": "range", "from_date": ...` (phẳng) hoặc `"period": "2025-11-01,2025-11-30"`, lặp lỗi validate 5 lần.
- Schema gửi lên vLLM là đúng (đã kiểm tra, inline, không `$ref`) → do năng lực model 9B với tham số lồng.
- **Sửa (không đổi schema):**
  - Step `repair_tool_calls`: gom field phẳng vào `period` / `filters`, parse JSON-text, ép số dạng chuỗi về int, `product_keys` chuỗi → list.
  - Prompt: ví dụ gọi đúng/sai.
  - `ToolNode(handle_tool_errors=_tool_error)`: lỗi tool kèm "call shape" đúng.

### 3.3 Model không biết dừng
- Sau khi có kết quả, model gọi lại tool y hệt, tự bịa tool `final_answer`, hoặc trả **content rỗng** (mọi thứ nằm trong thinking).
- **Sửa:** step `conclude_if_done`: các trường hợp trên → bỏ call, chuyển finalize với output tool thành công gần nhất làm kết luận. Prompt thêm luật dừng.

### 3.4 Finalize ra JSON rác — lỗi lớn nhất
- Guided `json_schema` (structured output) trên vLLM 0.33 + Qwen3.5 sinh rác, **kể cả khi tắt thinking**: `answer_json: "name11.21"`, JSON toàn whitespace ~3000 token.
- Benchmark 2 case thật × 3 lần:

| Cách finalize | Đúng | Thời gian |
|---|---|---|
| guided json_schema (thinking off) | 1/6 | 88 s |
| JSON qua text, thinking off | **6/6** | **1 s** |
| JSON qua text, thinking on | 6/6 | 13 s |

- **Sửa:** `_finalize_self_hosted`: xin JSON qua text với thinking off; parse lỗi → thử lại thinking on; vẫn lỗi → abstain. Agent node vẫn bật thinking.
- **Bug phụ phát hiện khi chạy full:** model hay ghi `"answer_json": 166285` (số) thay vì chuỗi; Pydantic v2 không tự ép int→str → validate lỗi → abstain. Ảnh hưởng ~219 câu. **Sửa:** ép `answer_json` / `reason` không phải chuỗi về `json.dumps(...)` trước khi validate. Sau sửa: 198/286 câu abstain chạy lại đã có trả lời.

### 3.5 Hạ tầng
- Không có `max_tokens` → có request sinh vô hạn, treo run. **Sửa:** `--max-tokens 16384` mặc định.
- Port-forward chết giữa chừng (~phút 11) → 186 câu `Connection error` → abstain. **Xử lý:** port-forward trong vòng lặp tự nối lại, chạy lại các id lỗi. (Nên dùng NodePort/Ingress nếu chạy lâu.)

## 5. Phân tích abstain còn lại (chưa sửa)

### 5.1 34 câu recursion limit
Không câu nào lặp lại call y hệt — model **đổi hướng liên tục** đến khi hết lượt (277 tool call / 34 câu). Nguyên nhân:

1. **Không hiểu viết tắt / không dấu → hiểu sai ý (~1/2):**

| Câu hỏi | Model hiểu |
|---|---|
| "2/25 **bi huy** bao nhieu don?" (bị huỷ) | tìm khách tên "bi huy", "bùi huy"… rồi đếm đơn 2 khách ngẫu nhiên |
| "Dthu bình quân một đh **T2/2026**" | tuần 05–11/01, rồi các quý, cuối cùng trả **Quý 2** (sai) |
| "**1-2026** bán bao nhiêu chiếc Xiaomi" | cả năm 2026, rồi mấy khoảng khác mới ra tháng 1 |
| "T6/2026 3 mặt hàng bán chạy" | tuần 09–15/02 → 15–21/06 → mới ra tháng 6 |
| "Le Son Trung… **no them**, **tra no**" (công nợ → OUT OF SCOPE) | tìm seller, customer… |

2. **Có kết quả rồi nhưng không dừng**, tiếp tục query kỳ khác.
3. **Dùng sai hàm `calculate`** (~15 lỗi): `first(r4.name, 3)`, `value()` thiếu tham số, `round(Series)`, `lambda`, `.filter()`.
4. **Câu nhiều bước thật sự khó** (~8): hiệu ứng tăng giá, % khách mua từ N đơn, phiếu bảo hành.

### 5.2 Đề xuất (chưa làm, chờ thống nhất)

| # | Thay đổi | Giải quyết |
|---|---|---|
| A | **Step chuẩn hoá câu hỏi** (code, không LLM) trước agent: bung viết tắt (dthu, bnhiu, đh, bi huy, no them / tra no…) và **parse sẵn kỳ** ("T2/2026", "2/25", "1-2026", "th3/2025", "quý 4/2025", "tuần rồi"…) → đưa vào USER message dạng gợi ý `period`; câu gốc giữ nguyên | 1 |
| B | Prompt: khi tool đã trả giá trị đúng kỳ được hỏi → trả lời ngay, không thử kỳ khác | 2 |
| C | Lỗi `calculate` kèm danh sách hàm + chữ ký đúng (`top(r1.name, 3)`, `first(r1.name)`…) | 3 |
| D | Còn ~2 bước trước recursion limit → ép finalize với kết quả đang có (finalize vẫn abstain nếu không rõ) | 2 |

Rủi ro: D tăng số câu trả lời nhưng cũng tăng câu sai (−1) — ví dụ "T2/2026" bị trả số Quý 2. Nên làm A trước, **đo trên train (có đáp án)** rồi mới quyết D.

### 5.3 130 câu OUT OF SCOPE
Ví dụ train biz_128 "tháng này tổng giá trị các phiếu nhập hàng" — đáp án `89526400` lấy từ `DanhSachNhapHang.xlsx` (cột "Cần trả NCC", rulebook §5). `data_std` chỉ convert file bán hàng nên agent trả OUT OF SCOPE → abstain (0 điểm thay vì −1 nếu đoán bằng doanh thu). Ước tính ~9% câu train thuộc nhóm nhập hàng / tồn kho / công nợ. Muốn ăn nhóm này cần convert thêm bảng `purchases` / `inventory` / `debts` + tool tương ứng.

### 6.1 Luồng graph sau khi sửa

```
START → agent ──(tool_calls)──→ tools ──→ agent …
          │                       └ handle_tool_errors=_tool_error (lỗi kèm call shape)
          │  trong agent: LLM (thinking on)
          │     → repair_tool_calls   (gom period/filters phẳng về schema)
          │     → conclude_if_done    (call bịa / lặp / content rỗng → kết luận bằng output tool cuối)
          └─(không tool_calls)──→ finalize ──→ END
                                    └ self-hosted: JSON qua text (thinking off → on) + ép answer_json về chuỗi
```

### 6.2 Prompt đã thêm (`prompts.py`, SYSTEM, sau mô tả `information_finder`)

```text
  `period` is ONE nested object whose `kind` picks the period; its other fields go INSIDE it, never next to it:
    {"measure": "qty_base", "period": {"kind": "month", "month": 5, "year": 2026}, "filters": {"product_keys": ["..."]}}
    {"measure": "revenue", "period": {"kind": "range", "from_date": "2025-11-01", "to_date": "2025-11-30"}}
    {"measure": "revenue", "period": {"kind": "last_n_days", "n": 7}}      {"measure": "order_count", "period": {"kind": "today"}}
  Wrong: "period": "month", "month": 5 (flat) or "period": "2025-11-01,2025-11-30" (string).
  When information_finder already prints the single value asked, that value is the answer: reply without calculate.
  To finish, reply in plain text with the answer and NO tool call (there is no answer/final_answer tool); never
  repeat a call whose output you already have.
```
(Trong file các `{}` được escape thành `{{ }}` vì SYSTEM đi qua `.format()`.)

Prompt finalize thêm (chỉ khi self-hosted), gửi sau `FINALIZE`:
```text
Reply with only one JSON object matching this schema, no other text:
<Submission.model_json_schema()>
```
